## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/whisper_asr_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 12-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent (on a fresh runtime all twelve: configs, tokenizer files, `README.md`, the 1.6 GB `model.safetensors`), from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` hands the verified directory to `AutoProcessor` / `AutoModelForSpeechSeq2Seq` with `trust_remote_code=False` (the Whisper implementation is the pinned `transformers==4.52.1` one; no model-repository code runs).
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/whisper_asr_input_manifest.json` with the schema, ceilings (`TASKS`, `MIN_CHUNK_LENGTH_S`, `MAX_CHUNK_LENGTH_S`), the observed input, the request, the verdict, and one recorded rejection finding (an oversized chunk length); `evaluation_report` (EVAL21) writes `outputs/whisper_asr_evaluation_report.json` — `sample-sanity` with `word_error_rate` when a reference transcript exists, `not-measurable` (with what labelled audio would make the task measurable) otherwise.
- The default sample is the first `validation` utterance of the public `hf-internal-testing/librispeech_asr_dummy` dataset, loaded through the pinned `datasets==4.4.0` at dataset revision `5be91486e11a2d616f4ec5db8d3fd248585ac07a` and decoded with the pinned `soundfile`; its WER is sanity evidence for one utterance, not a benchmark claim. `datasets` was promoted from the `tutorial` extra to a runtime pin so the standalone install cell carries it (ENV2/PAR2).
- WER normalisation is stated in the notebook and the card: case-folded, punctuation removed, curly apostrophes folded; abbreviations and numbers are not normalised.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; `REFERENCE_TEXT` defaults to empty (no reference → `not-measurable`).
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
